# Roadmap

Each item is one spec in `agent-os/specs/`. Ship in order; each step is usable on its own.

## Shipped

- **v1: ingest + ask** (`2026-10-13-zchut-v1-ingest-ask`), shipped 2026-10-13. `zchut ingest` fetches kolzchut.org.il and gov.il pages into Chroma through LlamaIndex, chunked by section headings with the title path and per-chunk url/title/section/fetched_at/license. `zchut ask "<question>"` prints a Hebrew answer with numbered citations and the page's last-updated date, or a fixed refusal when the best retrieval score is under the threshold. `eval/questions.json` holds 30 questions with expected source URLs; `zchut eval` reports retrieval hit@3, citation precision and refusal rate. Every AI call is recorded under `runs/`; `--max-usd` (default 0.05) aborts before the call that would exceed it.
- **v2: LangGraph conversation** (`2026-10-13-zchut-v2-conversation`), shipped 2026-10-13. `zchut ask` runs a LangGraph state graph: classify (topic, in scope, missing fact) -> one clarification interrupt (stdin or `--reply`) -> retrieve -> answer -> verify -> final, with refuse for out-of-scope or weak retrieval and escalate to the topic office from `config/offices.json` when verification fails. Answer tiers `--tier haiku | qwen-openrouter | vllm`, verifier tiers `--verifier haiku | jev`, `--no-verify`; `zchut chat` keeps history between questions; `zchut eval --tiers ... --verifiers ...` writes one report per combination and a side-by-side table with verification pass rate, escalation rate, cost per question and latency; `zchut cost --days N` sums `runs/` by command and model. Default `--max-usd` is now 0.08.
- **v3: full corpus** (`2026-10-13-zchut-v3-full-corpus`), shipped 2026-10-13. `zchut crawl plan` lists every כל זכות article through the MediaWiki `allpages` API, reads revisions in batches of 50 and diffs them against the local `data/manifest.json` (new, changed, unchanged, gone) with a time estimate; `zchut crawl run [--limit N] [--max-minutes M] [--max-usd X]` fetches, embeds and stores only new and changed articles, writes each manifest entry after the store replace, records errors and continues, deletes gone articles, and resumes where it stopped. The crawl record holds counts, elapsed, tokens and cost, never titles or text.

- **v4a: prompt tuning** (`2026-10-13-zchut-v4a-prompt-tuning`), shipped 2026-10-13. Plain-text answer rules (no Markdown, 6 lines, say what is missing), `clean_answer` with a stripped-marker count, `render_html` for Telegram, verifier wording, `eval/verifier_labels.json` with a verifier-accuracy column and a `markdown free` metric.
- **v4: Telegram** (`2026-10-13-zchut-v4-telegram`), shipped 2026-10-13. A FastAPI webhook (`src/zchut/bot/`) on Google Cloud Run (min 0, max 1 instance) checks Telegram's secret header, answers 200 and runs the conversation graph in the background, replying with the `render_html` answer; `/start` and `/help` give a fixed Hebrew text, unlisted chats get a refusal line. Clarifications wait in a Firestore session (`sessions/<chat_id>`, 30-minute TTL on `expires_at`); run records go to Firestore `runs` with hashes only and feed a daily budget cap and `zchut cost --source firestore`. `QdrantStore` implements the store interface (`store.backend: chroma | qdrant`) and `zchut store migrate --from chroma --to qdrant` copies the index with a count check. `zchut bot serve|simulate`, `Dockerfile`, `deploy/cloud-run.md` and `scripts/deploy.ps1` (run by the owner).
- **v4b: conversation quality** (`2026-10-15-zchut-v4b-conversation-quality`), shipped 2026-10-15. A `condense` node turns follow-ups and clarification replies into one standalone question (Haiku JSON schema) that drives retrieval, answer and verification; non-questions get a fixed nudge line with no search; clarifications are fixed questions from `config/clarifications.json`, at most once per session; office questions answer with the office entry (`office_lookup`); citations are renumbered in display order; `zchut eval --conversations` replays five conversations from the first live session and reports turn accuracy; `zchut chat` runs the bot's session flow.
- **v5: MCP server + re-ingest routine** (`2026-10-15-zchut-v5-mcp-and-reingest`), shipped 2026-10-15. `zchut mcp serve` runs a read-only stdio MCP server (official `mcp` SDK, `FastMCP`) with `search(query, k, topic)` (k capped at 20, query at most 500 chars, topics from `config.mcp.topics`) and `fetch(url)` (a page's chunks from the index, no network), plus the `zchut://stats` resource; every result carries the license and the CC BY-SA attribution line. `zchut crawl report [--notify]` prints the Hebrew diff of the last two crawl records and the manifest and can post it to Telegram (`report_posted` in the crawl record); `zchut notify "<text>"` sends one message to the single allowed chat. The README holds the client config and the weekly routine prompt.
- **v5b: hybrid retrieval** (`2026-10-15-zchut-v5b-hybrid-retrieval`), shipped 2026-10-15. BM25 over chunk text and title path (Hebrew prefix-stripping tokenizer, cached in `data/keyword-index.pkl` keyed by store count and newest manifest fetch date) fused with the vector ranking by reciprocal rank fusion (`k = 60`, top 50 each); refusal still uses the best vector score. `retrieval.mode: vector | hybrid` in config, `zchut eval --mode vector|hybrid` for both the question set and the conversations; the README holds the before/after table, the full-corpus row is the owner's run.
- **v6: framework comparison** (`2026-10-15-zchut-v6-framework-comparison`), shipped 2026-10-15. `LlamaChunker` (`MarkdownNodeParser` over the page rendered as Markdown headings, `SentenceSplitter` on the plain text) and `LlamaVoyageEmbedder` (`VoyageEmbedding` behind the `Embedder` protocol, cost estimated and marked `cost_estimated`) plug in behind the same seams; `chunk.engine` and `embed.engine` choose them (defaults `section`, `httpx`). `zchut ingest --engine --collection` and `zchut eval --retrieval-only --collection` work on named Chroma collections; `zchut compare [--dry-run]` scores the four combinations, writes `reports/compare-<date>.json` and prints a recommendation from a fixed rule (hit@3 at least the baseline, mean best score at least the baseline minus 0.02); nothing auto-switches. The README holds the dry-run table and the owner's real-run placeholder.

## Operations

- Budget: under 10 USD per month across all providers. Anthropic console hard limit, Voyage prepaid, OpenRouter prepaid; Chroma local and Qdrant Cloud free tier cost nothing.
- Every command takes `--max-usd` (default 0.08) and aborts before the call that would cross it; `zchut eval` over 30 questions on Haiku with verification should stay under 0.30 USD.
- Weekly: sum `runs/` for the week (`zchut cost --days 7`); if the month is on track to exceed 8 USD, switch the default tier to `qwen-openrouter`.
- Re-ingest with `zchut crawl run` (weekly routine, see the README); unchanged revisions are never re-embedded.
